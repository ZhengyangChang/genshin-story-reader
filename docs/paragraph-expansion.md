# 逐段展开：内容结构提案

状态：待实现。当前站点仍使用整篇简述 / 详述切换；本文记录下一步的内容格式与迁移方案。

## 阅读方式

每个叙事单元默认显示简述，点击明确的“展开这段”按钮后，在原位置替换为详述；可再收起。正文仍支持选中文字，不把整段设为点击区域。展开状态属于每个单元，彼此独立；“全部展开 / 收起”可作为次要操作。

彩蛋、背景、伏笔、收束卡片只在对应单元展开后出现，卡片本身仍默认折叠。简述保持连续正文，不显示小标题。场景标题仅是编辑组织信息，不要求显示到页面。

## 推荐格式：一幕一个 YAML 文件，正文用 Markdown

简述与详述不再分文件，也不用数组下标匹配。同一个 block 保存两种文字，用稳定 ID 标识。这里的单元按事件与因果划分，而不是按空行划分：一段简述可以对应多段详述。

下面只演示局部结构，正式文件继续保留版本、剧透范围、来源、发布时间等元数据：

```yaml
id: aq-6-2-act-5
title: 终北的夜行诗
scenes:
  - id: festival-coming
    title: 为归途准备一场节日
    blocks:
      - id: farewell-festival
        brief: |
          菈乌玛与法尔伽正在组织庆典。哥伦比娅答应参加，却还受神明身份与愚人众通缉所困。众人先分头筹备，也想为她选一份合适的送行礼物。
        detail: |
          此处存放围绕同一事件展开的完整叙述。

          可以包含多个 Markdown 段落，不要求与简述有相同段落数。
        sourceIds: [shadows]
        notes: []
```

示例 detail 是格式占位，不是可发布正文。来源应按实际对话记录核实。

保留 scene ID，兼容已有场景直达链接；block ID 在同一幕内唯一，新增更细的定位锚点。前言也应成为普通 block，不能留下无法展开的独立正文。

notes 沿用现有字段与 `[[文字|note-id]]` 引用语法，改为归属 block；来源集中放在整幕 sources 内。编译校验重复 ID、空简述、无效来源、越界或孤立的补充引用。尚无详述时省略 detail，页面不显示展开按钮，不能复制简述冒充详述。

## 为什么采用这个格式

- YAML 多行字符串可以直接写中文和 Markdown，简述与详述相邻，方便一起修改和审阅。
- JSON 的长文换行与引号编辑麻烦；TS/MDX 引入正文不需要的代码语法。
- 自定义 Markdown 容器也能实现，但需要新增嵌套语法和解析规则；目前优先选择结构明确、容易验证的记录格式。
- 构建时继续生成按幕加载的 JSON；源文件格式不要求浏览器运行时增加 YAML 解析。

## 迁移顺序

1. 以第五幕试点，逐个场景人工划分叙事单元，核对两种文字覆盖同一事件；不能自动按段落序号配对。必要时小幅重写简述，使范围对应。
2. 编译器暂时兼容旧格式与新格式，但禁止同一幕存在两套发布源。先接通验证、生成数据与逐段展开界面，再迁其余五幕。
3. 手机验证展开与收起后位置稳定、按钮容易点击、最大字号不溢出；使用 aria-expanded 和 aria-controls 支持键盘与读屏。
4. 保留旧阅读记录；先不把“展开过”视为“读完详述”。旧 mode=detailed 链接可映射为初始全部展开，普通访问仍默认简述。旧链接的显式 mode 优先。
5. 完成后更新正式内容模型文档，废弃两文件成对的写作要求。部署仍由手动发布流程控制。
