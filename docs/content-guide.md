# 内容规范

## 写作目标

读完能讲出这一幕发生了什么，也能理解关键人物为什么这样行动。以事件为骨架，用具体的经过支撑解释，不靠一串设定名词或评价句代替故事。

## 一幕怎么写

1. 开头用很短的承接说明眼前处境，只补这一幕需要的前情。
2. 按事件发生与信息揭示的顺序推进：发生了什么 → 人物如何回应 → 局面怎样改变。
3. 在关键选择、调查、交锋与反转处展开。保留能解释因果的线索，略去重复跑腿和玩法步骤。
4. 必要背景在首次需要理解时解释，不把所有背景堆在开头。
5. 结尾写这一幕留下的局面与未解问题，停在当前幕的信息上限。

每段承担一个清楚的动作、转折或解释。篇幅由情节决定，先不规定字数；避免为凑长而重复，也避免将一场关键戏压成一句结论。

## 事实与解释

- 正文用自己的话复述。可以解释有证据支持的动机和因果，解释不等于补写人物内心。
- 人物自己的判断要明确归于该人物；尚未证实的推断使用“她认为”“这里可以理解为”等恰当措辞。
- 不虚构对白、动作、能力限制、心理活动与时间顺序。
- 必要对白只作简短引用并标明来源位置；不把长段游戏台词搬进文章。
- 角色能力在这一幕实际发挥作用时解释，区分游戏战斗机制与剧情表现。
- 无法核实的内容留在核查笔记，不能靠流畅叙述掩盖不确定性。

## 来源工作流

优先对照游戏内任务文本、完整任务实录与官方发布资料；Wiki 可辅助定位，再用原始剧情核对关键事实。第三方文章和 AI 回答可提供查找线索，不能独自证明情节。

在 content/sources/ 记录：待核实主张、资料链接、任务段／视频时间点、核查结论、检查日期。叙述中的关键行动、能力与因果应能追到来源。

sources 列表与正文一起维护。正式文章保留可读的来源入口，不需要给每句话插一个脚注。

## 首篇与审阅

先围绕 6.1 奈芙尔相关情节写样章，核实其所在任务段、前后行动、能力表现和结果。样章确认叙述口吻后扩成完整一幕，避免单独抽取人物导致因果断裂。

发布前检查：人物名和幕名准确；行动顺序和关键因果有来源；不使用后续情报；段落能连续阅读；引用和图片权利记录完整。核查通过后将 status 从 review 改为 published。

## 当前内容策略

先逐幕完成简述，再写详述。主故事与额外解释分开；补充卡片仅在详述显示，默认折叠，注明证据性质和信息范围；简述只保留连续正文。具体元数据及语法见 content-model.md。6.0—6.3 的前八幕简述与详述初版均已接入；详述依据任务对话与过场记录，不等于逐镜头录像核查已完成。
