# 项目架构

状态：初稿，2026-10-14。本文记录实现方向，未标为完成的功能均为计划。

## 1. 要做什么

面向想补剧情、回顾故事、理解关键人物行动的中文读者。按版本与幕浏览，用连贯叙述还原事件经过，并在需要时解释背景和因果。

首批内容为 6.1 中奈芙尔相关情节及其所在的一幕。具体任务名、顺序与情节在写作阶段核实，不把其他项目的梗概作为事实底稿。

第一版不做角色百科、全量任务数据库、配队攻略、登录账号、云同步、在线编辑后台。先把文章和阅读体验做好。

## 2. 页面与导航

- 阅读入口：简短介绍、继续阅读、已有内容目录；没有阅读记录时进入首篇已发布文章。
- 阅读页：桌面左侧目录，中间正文，底部上一幕／下一幕；手机目录抽屉。
- 文章内部：一幕一篇，小标题连接场景；长文自然滚动，不按字数机械分页。
- 目录层级：版本 → 幕。角色专题后续以相关文章入口实现，不复制正文形成第二份事实来源。
- 参考资料：每幕末尾折叠显示。核查笔记保留在仓库，不混入叙述。
- 空状态：未写的幕不伪装成可读内容；显示覆盖范围。

## 3. 内容与标识

正文采用 UTF-8 Markdown 加 YAML 元数据，目录由构建过程自动生成。每幕一个文件；同一版本可容纳多幕。标题与文件顺序不作为身份。

初始字段约定（模板见 content/templates/act.md）：

| 字段 | 含义 |
| --- | --- |
| id | 固定文章 ID，例如 aq-6-1-act-4；发布后不随改名变化 |
| version | 字符串版本号，例如 "6.1" |
| arc | 故事章节／系列名称，核实后填写 |
| act | 幕序号，数值 |
| title | 核实后的标题 |
| order | 版本内阅读顺序；只改变顺序，不改变 ID |
| status | draft / review / published |
| spoilerThrough | 内容揭示上限，包含版本与幕 |
| updated | 最近人工修订日期，YYYY-MM-DD |
| sources | source ID、标题、URL；需要时附任务段或视频时间点 |

只有 published 进入公开目录、构建结果和站内搜索；草稿不得打包到发布产物。sources 至少有一项有效资料后才能发布。

场景小标题配置显式、稳定的锚点；避免由标题文字自动生成唯一身份。文章地址建议 `#/story/aq-6-1-act-4`，场景地址附稳定 scene ID。静态托管无需配置服务端路由。

版本按主次版本数值排序，不能用字符串排序。构建时验证 ID 唯一、元数据完整、sources 有效格式和关联目标存在。本文定义的格式需要在实现阶段用真实样章验证。

## 4. 技术方案

第一版建议 Vite + TypeScript + 普通 CSS，使用 Markdown 解析与 YAML 元数据解析依赖；不引入应用框架或数据库。这里是实现选型，当前尚未安装依赖，也没有构建命令。

数据流：Markdown 源文件 → 构建时校验与转换 → 不含草稿的目录及文章 HTML/JSON → 静态阅读器。

Markdown 禁止任意原始 HTML，链接只允许安全协议，图片默认使用审查过的本地素材。正文和目录分开输出，以便以后按篇加载。避免将全站长文塞进单个脚本。

阅读器负责目录、文章渲染、路由、防剧透、主题、字号、行宽、阅读记录。正文样式单独维护，方便只改文章而不改页面。

## 5. 阅读状态

浏览器本地保存 schemaVersion、lastArticleId、lastSceneId、visitedArticleIds、completedArticleIds、theme、fontSize、lineWidth。

进入文章只记为访问，不能直接算读完。通过“标记读完”记录完成状态；自动恢复优先使用场景锚点。正文重排或新增文章不应破坏旧记录。

解析失败或存储不可用时仍可阅读。导入记录校验格式及 ID；对不存在的文章忽略并给出提示。导出／导入支持跨设备手动迁移，更换域名不会自动继承 localStorage。

## 6. 防剧透

正文以旅行者／读者在该幕当时能知道的信息展开。后续揭示不倒灌进早期章节。

未访问文章使用中性目录标签（版本、幕序号），隐藏可能剧透的标题；点击后揭示。前后篇提示、页面标题、预览摘要与未来搜索结果遵循同样规则。正文小标题保持中性，避免提前写出结局。

访问和完成状态都由用户控制；不把防剧透设计成限制跳读。

## 7. 部署边界

先本地预览。内容和阅读器验收后再选择发布平台，静态产物可适配 GitHub Pages 或 Netlify。私有源码不等于部署站点私有，发布时明确核实可见性与平台支持，不自动开启公共站点。

子路径部署需验证资源地址；CI 后续执行元数据校验、类型检查与构建。现在不创建虚假的部署工作流或运行说明。
