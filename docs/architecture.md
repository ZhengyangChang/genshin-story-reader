# 项目架构

状态：2026-10-14 已搭建 Bun + TanStack Start 工程。具体实现与限制见 development.md；本文中未完成的内容仍为目标。

## 1. 要做什么

面向想补剧情、回顾故事、理解关键人物行动的中文读者。按版本与幕浏览，用连贯叙述还原事件经过，并在需要时解释背景和因果。

内容已覆盖《空月之歌》第一至第六幕：6.0 的“雪浪与苍林之舞”“尘与灯的挽歌”，6.1 的“不存在的国土”“回望湮灭的月光”，以及 6.2 的“终北的夜行诗”“散于晨雾的月芒”，均有独立简述与详述初版。前两幕对照八个完整任务对话表，记录见 content/sources/6.0.md；第五、第六幕对照五个完整任务及节庆对话表，记录见 content/sources/6.2.md。以游戏任务记录核对，不把参考项目的梗概作为事实底稿。

第一版不做角色百科、全量任务数据库、配队攻略、登录账号、云同步、在线编辑后台。先把文章和阅读体验做好。

## 2. 页面与导航

- 阅读入口：简短介绍、继续阅读、已有内容目录；没有阅读记录时进入首篇已发布文章。
- 阅读页：桌面左侧目录，中间正文，底部上一幕／下一幕；手机目录抽屉。
- 文章内部：一幕一篇，小标题连接场景；长文自然滚动，不按字数机械分页。
- 目录层级：版本 → 幕。角色专题后续以相关文章入口实现，不复制正文形成第二份事实来源。
- 参考资料：每幕末尾折叠显示。核查笔记保留在仓库，不混入叙述。
- 空状态：未写的幕不伪装成可读内容；显示覆盖范围。

## 3. 内容与标识

正文采用 UTF-8 Markdown 加 YAML 元数据，目录由构建过程自动生成。每幕一个 paired 文件，blocks 内的每条记录用稳定 ID 同时保存 brief 与 detail，编译后目录中只显示一幕。标题与文件顺序不作为身份。

初始字段约定（模板见 content/templates/act.md）：

| 字段           | 含义                                               |
| -------------- | -------------------------------------------------- |
| id             | 固定文章 ID，例如 aq-6-1-act-4；发布后不随改名变化 |
| version        | 字符串版本号，例如 "6.1"                           |
| arc            | 故事章节／系列名称，核实后填写                     |
| act            | 幕序号，数值                                       |
| title          | 核实后的标题                                       |
| order          | 版本内阅读顺序；只改变顺序，不改变 ID              |
| status         | draft / review / published                         |
| spoilerThrough | 内容揭示上限，包含版本与幕                         |
| updated        | 最近人工修订日期，YYYY-MM-DD                       |
| sources        | source ID、标题、URL；需要时附任务段或视频时间点   |

只有 published 进入公开目录、构建结果和站内搜索；草稿不得打包到发布产物。sources 至少有一项有效资料后才能发布。

场景标题采用 `## stable-scene-id | 标题`，构建时生成固定锚点。文章使用 TanStack 文件路由 `/story/aq-6-1-act-4`，场景链接附 `#stable-scene-id`。直接访问由 Start 服务处理；静态托管需要后续预渲染和路由方案。

版本按主次版本数值排序，不能用字符串排序。构建时验证 ID 唯一、元数据完整、sources 有效格式和关联目标存在。已用前六幕简述与详述验证；多叙述版本、补充卡片和点击揭示的约定见 content-model.md。

## 4. 技术方案

已采用 Bun + TanStack Start + React + TypeScript + Vite + 普通 CSS。gray-matter 解析 YAML 元数据，Zod 校验结构，markdown-it 渲染正文。依赖已安装并锁定，命令见 README；当前不引入数据库。

数据流：Markdown 源文件 → 构建时校验与转换 → 不含草稿的目录及文章 HTML/JSON → 静态阅读器。

Markdown 禁止任意原始 HTML，链接只允许安全协议，图片默认使用审查过的本地素材。正文和目录分开输出，以便以后按篇加载。避免将全站长文塞进单个脚本。

阅读器负责目录、文章渲染、路由、防剧透、主题、字号、行宽、阅读记录。正文样式单独维护，方便只改文章而不改页面。

## 5. 阅读状态

浏览器本地保存 schemaVersion、lastArticleId、visitedArticleIds、completedArticleIds、completedEditionKeys、readingMode、theme、fontSize、lineWidth。readingMode 为旧版兼容字段，普通访问默认逐段简述。读完状态按文章 ID 与篇幅分别记录；旧记录迁移为简述读完。lastSceneId 为后续跨会话恢复目标，尚未保存。

进入文章只记为访问，不能直接算读完。通过“标记读完”记录完成状态；逐段展开使用稳定单元锚点，收起长文时保持段首可见；跨会话目前只恢复文章。正文重排或新增文章不应破坏旧记录。

目前记录保存文章级进度；lastSceneId 和场景位置恢复尚待实现。解析失败或存储不可用时仍可阅读。导入记录校验格式及 ID；对不存在的文章忽略并给出提示。导出／导入支持跨设备手动迁移，更换域名不会自动继承 localStorage。

## 6. 防剧透

正文以旅行者／读者在该幕当时能知道的信息展开。后续揭示不倒灌进早期章节。

未访问文章使用中性目录标签（版本、幕序号），隐藏可能剧透的标题；点击后揭示。前后篇提示、页面标题、预览摘要与未来搜索结果遵循同样规则。正文小标题保持中性，避免提前写出结局。

访问和完成状态都由用户控制；不把防剧透设计成限制跳读。

## 7. 部署边界

仓库已公开，发布目标为 GitHub Pages。普通 build 保留 Start 构建；build:pages 启用静态预渲染，输出可独立托管的首页、文章页和 404。子路径为 /genshin-story-reader/。Pages 来源已设为 GitHub Actions，但发布仅限手动触发，本次不部署。

已配置 CI 执行元数据校验、类型检查、测试、普通构建与 Pages 静态构建。手动部署流程需要输入 PUBLISH；push 不触发部署。静态产物不加入 Git 历史。详见 deployment.md。

## 8. 补充与手机阅读

主线正文之外的背景、彩蛋、收束、伏笔以默认折叠卡片显示，放在所属场景末尾。正文用 `[[显示文本|note-id]]` 打开对应卡片，不依赖 hover。推断单独标明；后续信息卡片在展开前隐藏可能剧透的标题，答案不进入折叠状态的 DOM。

手机采用单栏正文与置顶目录入口，点击段落展开；按钮至少 44px 高，卡片就地展开。验收覆盖 320／390px、字号最大值和卡片展开状态。实现细节见 content-model.md。
